Cross-cutting: latency, order, shared resources
At 50 fps each stage has 20 ms per frame; the under-50 ms end-to-end target leaves about 2.5 frames, so look-ahead is ruled out and every stage must be pipelined across ISP, GPU, NPU and VPU.
Proposed pipeline order
Sensor / ISP: demosaic, HDR, AE/AGC (ISP)
Stabilization: gray, pyramid, optical flow, features (GPU)
Homography, smoothing (CPU)
Warp (GPU)
Turbulence fusion, if enabled (GPU)
Super-resolution, Y channel (NPU or GPU)
Chroma upscale and merge (GPU)
Encode / display (VPU / display controller)
Stabilization runs before super-resolution because it is 4 to 9x cheaper at 640x480 and gives the SR model steady input.
Watch out for
Look-ahead is ruled out: each future frame costs 20 ms of the 50 ms budget, so no centered smoothing window and no future frames in turbulence fusion.
The NPU is shared: SR and any AI turbulence model compete for 2.3 TOPS.
The GPU is shared: stabilization, warp, chroma merge and classical turbulence fusion all run there.
